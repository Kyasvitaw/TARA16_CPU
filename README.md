# TARA-16 Microprogrammed CPU in Logisim-Evolution

A complete 16-bit processor for the **TARA** instruction set, built gate-by-gate in **Logisim-Evolution 4.1.0** for the CS2310 (Computer Organisation) take-home lab at IIT Madras.

The CPU has a bus-based datapath, an 8×16 register file, an ALU with status flags, byte-addressable big-endian memory, and a **microprogrammed control unit**. The control unit is a 2048 × 32 control ROM whose contents are generated by a Python script.

| | |
|---|---|
| **Tool** | Logisim-Evolution 4.1.0 |
| **Instructions implemented** | 26 / 26 graded (MUL intentionally halts) |
| **Verification** | 27 / 27 programs identical to the reference simulator (TARA Studio): registers, PC and all 2048 bytes of memory |
| **Microcode checks** | 7 / 7 consistency checks pass |

## Features
- **The full TARA ISA**, apart from MUL:

  | Class | Instructions |
  |---|---|
  | Control | NOP, HLT |
  | Moves and immediates | MOV, LIL, LIH |
  | Memory | LDW, STW, LDB, STB |
  | Arithmetic | ADD, SUB, ADDI |
  | Logic | AND, OR, XOR, NOT |
  | Shifts and compare | SHL, SHR, SLT |
  | Branches and jumps | BZ, BN, JMP |
  | Subroutines | CALL, RET |
  | Stack | PUSH, POP |

- **Microprogrammed control.** The ROM address is `{Z, N, OPCODE[4:0], TSTATE[3:0]}`, and each ROM word is the 32-bit control word for one clock.
- **The microcode is generated, not hand-typed.** `G38_th6_microcode_gen.py` builds all 2048 ROM words and checks them (bus conflicts, missing STEP_RESET, branch encoding and so on) before writing the hex file.
- **Byte lanes.** LDB and STB read or write a single byte without a read-modify-write cycle.
- **Stack and subroutines.** CALL links through R6, and R7 is the stack pointer.
- **Behaviour identical to the reference.** It matches TARA Studio (`taracpu` 1.3.1) on every test program.

## Architecture

```
            ┌───────────────────── control_unit ─────────────────────┐
            │  T-state counter ──┐                                   │
 Z, N ─────►│  opcode ──────────►├─► 2048×32 CONTROL ROM ─► HALT mux ─┼──► cw[31:0]
            │                    │   addr = {Z,N,op,T}               │      │
            └────────────────────────────────────────────────────────┘      │ splitter
                                                                            ▼
 ┌──────────────────────────────── tara_datapath ──────────────────────────────────┐
 │  PC ─ MAR ─ MDR ─ IR ──► tara_decoder ──► imm_unit                             │
 │    │     │     │                                                               │
 │ ═══╪═════╪═════╪═════════════ 16-bit shared bus ════════════════════════════   │
 │    │     │     │            │                 │                                │
 │  ram_word (2×8-bit RAM,  regfile8x16      ALU (A: qa/PC, B: qb/IMM)            │
 │  byte lanes)             R0–R7            └► status_reg (Z N C V) ─► Z, N      │
 └─────────────────────────────────────────────────────────────────────────────────┘
```

**Subcircuits**

| Subcircuit | Role |
|---|---|
| `tara_cpu` | Top level: clock, reset, control-word splitter |
| `control_unit` | 4-bit T-state counter, control ROM, HALTED flip-flop |
| `tara_datapath` | Bus, tri-state drivers, operand and index muxes |
| `PC_MAR_MDR_IR` | Program counter (+2 or load), MAR, MDR, IR |
| `tara_decoder` | Splits the IR into its opcode, register and immediate fields |
| `imm_unit` | 8 immediate forms: zext8, sext8, sext5, rel8×2, rel11×2, const 2, LIH, zero |
| `regfile8x16` | 8 × 16-bit registers, two read ports and one write port |
| `ALU` | ADD SUB AND OR XOR NOT SHL SHR SLT, plus pass-through; outputs Z N C V |
| `ram_word` | Two 8-bit RAMs: bottom RAM = high byte, top RAM = low byte; BYTE_MODE selects one lane |

![ram_word byte lanes](docs/images/ram_word.png)
*`ram_word`: in byte mode, only the bank chosen by `addr[0]` is written, and a read is zero-extended.*

### Instruction timing
Every instruction starts with the same three fetch cycles:

| T | Control word | Action |
|---|---|---|
| T0 | `0x00000041` | PC → MAR |
| T1 | `0x000014A0` | M[MAR] → MDR, PC ← PC + 2 |
| T2 | `0x00000102` | MDR → IR |

The execute steps start at T3 and finish with `STEP_RESET`. For example, `LDW R1, 0(R2)`:

| T | ROM address | Control word | Action |
|---|---|---|---|
| T3 | `0x053` | `0x00924050` | MAR ← R2 + sext5(0) |
| T4 | `0x054` | `0x000010A0` | MDR ← M[MAR] |
| T5 | `0x055` | `0x20000202` | R1 ← MDR, STEP_RESET |

**Branches.** BZ and BN latch the flags of Rt at T3. The ROM row used at T4 is then chosen by the latched Z or N bit, which is part of the ROM address.

## Control word (32 bits)

| Bit(s) | Signal | Bit(s) | Signal |
|---|---|---|---|
| 0 | PC_OUT | 12 | mem_read |
| 1 | MDR_OUT | 13 | mem_write |
| 2 | IMM_OUT | 14–18 | ALU_select |
| 3 | RF_OUT | 19 | ALU_A_SEL (qa / PC) |
| 4 | ALU_OUT | 20 | ALU_B_SEL (qb / IMM) |
| 5 | RAM_OUT_LD | 21 | status_we |
| 6 | MAR_LOAD | 22–24 | IMM_SEL |
| 7 | MDR_LOAD | 25–26 | RA_SEL (RA, RD, R6, R7) |
| 8 | IR_LOAD | 27–28 | RF_IDX_SEL (RD, R6, R7) |
| 9 | RF_WRITE | 29 | STEP_RESET |
| 10 | PC_EN | 30 | HALT |
| 11 | PC_LOAD | 31 | BYTE_MODE |

## Running a program

**Prerequisites:** Java and [Logisim-Evolution 4.1.0](https://github.com/logisim-evolution/logisim-evolution), plus Python 3 with `pip install taracpu`. The `taracpu` package provides the assembler and reference simulator.

**1. Assemble the program into memory images**
```bash
python3 tools/make_images.py myprog.tara
# → myprog_LOW.hex  (low bytes  → TOP RAM)
# → myprog_HIGH.hex (high bytes → BOTTOM RAM)
# The script also prints the final registers from TARA Studio, for comparison.
```
Ready-made images for all 27 test programs are in `th6/tests/memory_images/`.

**2. Load into Logisim**
1. Open `th6/G38_th6_tara.circ`. The main circuit is `tara_cpu`.
2. **Simulate → Reset Simulation** (Ctrl+R).
3. Go into `tara_datapath` → `ram_word`:
   - right-click the **top** RAM → *Load Image* → `_LOW.hex`
   - right-click the **bottom** RAM → *Load Image* → `_HIGH.hex`
4. The control ROM already contains `G38_th6_control_rom.hex`, because it is saved in the `.circ` file.

**3. Run**
- **Ctrl+K** (Ticks Enabled) runs the program. Ctrl+T steps one clock at a time.
- The program has finished when `HALTED = 1` in `control_unit`.
- Read R0–R7 in `regfile8x16`, and memory via *Edit Contents* on the RAMs. Word address = byte address / 2.

## Regenerating the microcode
```bash
cd th6
python3 G38_th6_microcode_gen.py              # --group 38 (default) --out .
```
This writes `G38_th6_control_rom.hex`, the listing and the check log. The script refuses to write a ROM that fails any of its 7 checks.

The microprograms live in the `EXEC` table inside the script. Each entry is a list of control words built with `pack(...)`, for example:
```python
"LDW": [EA, MEM_TO_MDR, MDR_TO_RD],
"RET": [pack(RA_SEL=2, RF_OUT=1, PC_EN=1, PC_LOAD=1, STEP_RESET=1)],
```
After regenerating, right-click the control ROM in Logisim, choose *Load Image*, and pick the new hex file.

## Verification
Each program was assembled with TARA Studio's own assembler and run to `HALTED = 1` on this circuit. The result was then compared with TARA Studio's CPU model.

| Suite | Programs | Result |
|---|---|---|
| Unit tests | t01–t21: every instruction, plus edge cases such as 7FFF+1, shifts by 0, 15, 16 and 33, sext5 −16, POP underflow, and all register-file ports | **21 / 21** |
| Integration | p1 register addition, p2 memory subtraction, p3 parity, p4 multiply by repeated addition, p5 array sum, p6 array max | **6 / 6** |

A program passes only if **R0–R7, the PC and all 2048 bytes of memory** match. Full results are in [`th6/tests/RESULTS.txt`](th6/tests/RESULTS.txt).

## Known limitations
- **MUL is not implemented.** Opcode 12 and the undefined opcodes 27–31 halt without changing any state (test t21).
- **Memory addresses are not wrapped.** `ram_word` uses a 15-bit word address, so addresses above `0x7FF` are not wrapped as they are in TARA's 2 KB memory. No test program uses them.
- **Word accesses must be aligned.** Word accesses ignore `addr[0]`.
